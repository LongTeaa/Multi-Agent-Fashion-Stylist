## Findings

### 1. [P2] Explicit YOLO selection is overridden by the default fake Vision provider

[dependencies.py, lines 185–188](https://github.com/LongTeaa/Multi-Agent-Fashion-Stylist/blob/603305e06e1880332548488e42c6d15082d82f8d/backend/app/core/dependencies.py#L185-L188)

`get_detector()` returns `FakeDetector` whenever `vision_provider == "fake"`, even when the caller explicitly selected `detector_backend="yolo_world"`. This prevents using real local detection with offline attribute extraction. It also makes the PR's own YOLO dependency-injection tests fail in a clean environment without a developer `.env` file. Respect the explicit detector selection and isolate test configuration using fixtures/dependency overrides. If this configuration combination is intentionally unsupported, validate it explicitly and align the tests and configuration documentation.

Reproduction from the review worktree's `backend` directory:

```powershell
python -m pytest tests/unit/test_yolo_world_detector.py::TestYoloWorldDependencyInjection -q --tb=short
```

Result: **2 failed, 1 passed**. Both the YOLO-success test and missing-model Gemini-fallback test receive `FakeDetector`.

### 2. [P2] Duplicate suppression removes distinct overlapping clothing layers

[yolo_world_detector.py, lines 294–300](https://github.com/LongTeaa/Multi-Agent-Fashion-Stylist/blob/603305e06e1880332548488e42c6d15082d82f8d/backend/app/services/yolo_world_detector.py#L294-L300)

The second NMS pass combines every non-person class. Consequently, it suppresses legitimate layers such as a shirt under a jacket whenever their rectangles overlap sufficiently. A tensor probe with jacket `[150,120,450,420,0.95,5]` and shirt `[160,130,440,410,0.90,3]` returns only `jacket` (IoU approximately 0.87). The missing shirt cannot be reviewed or confirmed. Restrict cross-class suppression to compatible duplicate/synonym groups and preserve distinct layers. Add a regression with overlapping outerwear and an inner top.

### 3. [P2] Detector padding is persisted as the original detector rectangle

[yolo_world_detector.py, lines 319–337](https://github.com/LongTeaa/Multi-Agent-Fashion-Stylist/blob/603305e06e1880332548488e42c6d15082d82f8d/backend/app/services/yolo_world_detector.py#L319-L337)

YOLO expands every rectangle before returning `DetectionResult`. Ingestion subsequently captures these coordinates in `raw_detection_boxes` and persists them as `raw_bounding_box`. For the jacket probe, the original normalized rectangle `(0.234375,0.1875,0.703125,0.65625)` becomes `(0.2109,0.1641,0.7266,0.6797)` before capture. The true original coordinates are lost, and restoring the original detection region cannot undo the margin.

This conflicts with `DATA_SCHEMA.md` (`raw_bounding_box` is the rectangle before automatic margin/manual edits) and `INGESTION_AND_RETRIEVAL_SPEC.md` (raw coordinates remain separate from the effective crop). The blanket expansion also bypasses the existing `isolated-footwear-margin-v1` guards. Return unpadded detector rectangles, capture them first, and apply effective-crop policy separately. Any intentional new crop policy needs a specification update and corresponding tests in the same change.

### 4. [P2] Garment aspect ratio is incorrect on non-square source images

[ingestion_service.py, lines 73–84](https://github.com/LongTeaa/Multi-Agent-Fashion-Stylist/blob/603305e06e1880332548488e42c6d15082d82f8d/backend/app/services/ingestion_service.py#L73-L84)

The aspect ratio divides normalized X span by normalized Y span, although these axes have different pixel scales on non-square images. A square 200×200 garment region in a 400×800 portrait image has box `(0.25,0.25,0.75,0.5)`. The function reports `aspect_ratio=2.0`, `shape_type="wide_horizontal"`, instead of ratio 1.0. This incorrect garment-proportion hint is inserted into the Gemini extraction prompt and can mislead fit/length interpretation. Calculate proportions from crop pixel dimensions or include the source width and height.

### 5. [P2] Person-only detection is treated as an ordinary garment proposal

[classifier.py, lines 149–156](https://github.com/LongTeaa/Multi-Agent-Fashion-Stylist/blob/603305e06e1880332548488e42c6d15082d82f8d/backend/app/services/classifier.py#L149-L156)

When the detector finds a person but no garments, the classifier retains person boxes as item candidates without adding a warning. A `person` box `(0.2,0.05,0.8,0.95)` with confidence 0.99 returns `worn_outfit`, one person candidate, and no quality warnings. Because this is a nonempty rectangle covering less than 95% of the frame, it bypasses ingestion's existing no-separation/full-frame warnings. It can therefore send a face-containing person crop through attribute extraction and ordinary wardrobe confirmation. The new Gemini prompt explicitly requests person boxes, making this fallback newly reachable through normal provider output.

Keep the person rectangle as spatial reference only. If no garment regions exist, enter the existing explicitly warned manual-review path or require clearer item photographs, as the ingestion specification requires.
